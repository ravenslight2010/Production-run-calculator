# Track inventory accurately from a fresh physical count

## What & Why
V2's first usable release includes full inventory, but run control Task #3909 does not build it. This follow-up adds auditable inventory operations and starts V2 balances from a fresh physical count, never from V1 stock or history.

## Done looks like
- Item and location setup, lots, and on-hand totals have clear server-owned identities and units.
- Receiving, transfer, count, correction, and run-consumption movements update stock and the append-only ledger atomically and idempotently.
- Competing corrections produce an explicit conflict rather than silently overwriting newer stock.
- A manager-reviewed V2 opening count records the physical baseline; no V1 balances, lots, or movement history are imported.
- Two devices converge on accepted inventory state and show stale/read-only status while offline.

## Out of scope
- V1 production writes, live cutover, or copying V1 inventory balances.
- Full workbook import workflows and full station-specific UI.
- Replacing the run lifecycle and command foundation owned by Task #3909.

## Steps
1. Define V2 item, location, lot, ledger, count, and operation-receipt contracts from the approved architecture.
2. Implement transactional inventory commands and server-calculated on-hand projections.
3. Build receiving, movement, correction, count review, and fresh-opening-count flows.
4. Integrate run consumption with the canonical run completion operation and test retries, races, and reload recovery on synthetic data.
