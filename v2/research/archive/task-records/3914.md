# Give V2 staff secure sign-in with existing roles

## What & Why
The owner approved carrying staff identities and roles into V2, but every person must sign in again. V2 must not inherit V1 sessions, reset tokens, or production credentials.

## Done looks like
- Implement V2-owned authentication and session storage with permission checks for run actions.
- Define a safe staff-and-role transfer that can be rehearsed and audited.
- Require fresh sign-in and invalidate transferred or stale session material.
- Verify staff cannot perform manager-only actions and that authorization derives from the server session, never client-supplied identity.
- Keep the implementation behind the separate-project and separate-database boundary.
