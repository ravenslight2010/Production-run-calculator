# Keep every production station aligned with the active run

## What & Why
V2 includes every production station. Task #3909 establishes the canonical run lifecycle and explicitly excludes the full station-by-station workflows. This follow-up gives operators station-specific production actions that persist against the shared run.

## Done looks like
- Every owner-approved production station has a responsive web/PWA workflow mapped to the canonical V2 run.
- Station inputs and progress are validated and accepted by the server; devices never treat local timer or progress state as authoritative.
- Concurrent edits, stale revisions, wake/reconnect, and read-only offline behavior are visible and recoverable.
- Station-specific timer and auto-track behavior is covered without duplicating committed progress.

## Out of scope
- Replacing the run lifecycle, command receipts, or worker lease foundation from Task #3909.
- V2 inventory, import/cutover data transfer, and production deployment.
- V1 production changes or writes.

1. Inventory current station workflows as read-only references and map them to the owner-approved V2 station scope.
2. Define station-specific server state and commands that use V2 run revisions and authorization.
3. Build the responsive station screens and canonical snapshot adoption behavior.
4. Test two-device races, stale commands, wake/reconnect, pause/resume, and station timer recovery using synthetic data.
