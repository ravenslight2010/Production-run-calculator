---
name: Release guide authority claims
description: How to keep production-publisher documentation checks precise without banning valid provider references.
---

When checking public release guidance, distinguish an active claim that a
provider publishes or proves the live app from accurate mentions of CI,
historical procedures, and examples. Preserve clear negative and historical
context, and report the document and exact claim so maintainers can fix it.

**Why:** Provider-name keyword bans flag correct CI and legacy explanations,
while a broad historical exception can hide a contradictory current claim in
the same paragraph.

**How to apply:** Keep the maintained document set explicit; test current
provider claims, live-proof claims, explicit denials, examples, historical
instructions, and nearby unrelated provider mentions.
