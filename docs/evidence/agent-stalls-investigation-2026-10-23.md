## Repository-controlled changes

### Before

- The post-merge hook had no phase-start/end markers. A failure or long pause after setup began could only be narrowed to the whole hook using its outer completion/timeout result.
- The artifact cleanup script selected recognized `pnpm --filter @workspace/{api-server,run-calculator,mockup-sandbox} run dev` process groups but logged the entire matching command line.

### After

- The hook emits a UTC start marker and then a UTC end marker with elapsed whole seconds, outcome, and exit code for the pinned-runtime preflight, targeted workflow cleanup, Corepack enable, frozen dependency install, each schema-push attempt, and publish preparation.
- Phase names are validated as lowercase fixed-format tokens. No command arguments, environment values, process command lines, database output, or test output are added to the new phase records.
- Failure exit status is preserved, later phases do not run after a failed non-retry phase, and schema push remains bounded to its existing four attempts and retry delay.
- Artifact cleanup still uses command-line matching only to recognize the existing process family, but its retained/output identity is now only the artifact class and process-group number.

These are observability/privacy repairs, not demonstrated Agent stall causes.

1.
